## Prioritized problems

### 1. P2 — Restore the consecutive DST overlap attempts and their geometry assertions

- **Old:** `premium/packages/vanilla-scheduler-tests/src/timeline/timeline-dst-instant-fidelity.ts:201`, “does not falsely detect overlap between the two fold copies”; especially old lines 222–239.
- **New:** `premium/packages/vanilla-scheduler-tests/src/event-drag/timeline.ts:339` (the `eventOverlap:false` table, with its fresh-calendar helper at line 250).

The old test moved the **same event** from midnight to the free first 01:30 occurrence, verified its rendered range over slots 3–4, then attempted a second drag onto the occupied second 01:30 occurrence. It required the second attempt to be rejected, the total successful drop count to remain one, and the event's API start **and rendered edges** to remain at the first occurrence.

The new table runs the allowed and rejected attempts on **different freshly initialized calendars**. Its rejected row starts at midnight and expects midnight after rejection. It also checks the start instant and callback count without asserting the old slot-span geometry. Thus it no longer protects rejection/restoration of an event that already acquired exact-instant state through a successful first drag, or a wrong visual restoration despite a correct API value. This is not the documented round-trip consolidation: that separate round trip is now actually present.

**Suggestion:** Keep the current positive/negative rows if useful, and restore one sequential test: drag to slot 3; assert `05:30Z` and both edges at slots 3–4; drag that same rendered segment toward slot 5; require no additional `eventDrop`, the unchanged first-copy start/end, and the same slots 3–4 geometry. Use `TimelineModel`, real pointer input, and `waitForSettle()`.

### 2. P2 — #3118 no longer verifies the touch resize callback or its revert

- **Old:** `standard/packages/vanilla-tests/src/legacy/event-resize.ts:57`, “should have correct arguments with a whole-day delta”, inside the touch/#3118 block; old lines 68–82.
- **New:** `standard/packages/vanilla-tests/src/event-resize/daygrid.ts:134`.

Both `eventStartEditable:true/false` rows, the original June 11→16 gesture, and real touch selection/resizing survive. However, the new test only inspects the final `endStr`. The old `waitEventResize` also required an **eventResize callback**, asserted a five-day `endDelta` and unchanged start, then called that touch operation's `revert()` and required the original start and **null end** to return.

The general mouse callback/revert tests in `event-resize/callbacks.ts` and mouse delta test in `event-resize/daygrid.ts:18` cover useful shared behavior, but do not exercise callback delivery or reverting after touch selection with either start-editability setting. A port can therefore pass if touch changes the date but fails to deliver the resize callback, reports a wrong delta, or cannot restore its original null end.

**Suggestion:** Add an `eventResize` spy to each existing #3118 row. Require exactly one call; assert `endDelta === createDuration({ days: 5 })`, unchanged June 11 start, and June 17 end; invoke that callback's `revert()`, settle, then assert June 11 start and `end === null`.

### 3. P3 — Restore the shared #8064 label on the two custom-format nav-link regressions

- **New:** `premium/packages/vanilla-scheduler-tests/src/navigation/timeline.ts:34` (hourly custom-format table row) and `:49` (daily custom-format case).

Both behaviors survive, with stronger label/row assertions. The old nearby `fullcalendar/issues/8064#issuecomment-4309593371` reference is gone from the new file.
